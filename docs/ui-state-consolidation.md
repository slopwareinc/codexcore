# UI State Consolidation

CodexCore already has the right low-level owner for app-server notifications: `CodexCoreStore`.
The store receives events from `CodexClient`, reduces them into thread/turn snapshots, and should remain the single source of truth for protocol state.

This slice consolidates the next layer up: rich UI transcript projection.
`CodexChatTranscriptProjection` now owns the mapping from store-shaped `CodexTurnSnapshot` / `CodexTimelineItem` values into `CodexChatMessage` values.
When live fallback code only has a raw `ThreadItem`, it first goes through `CodexTimelineItemMapper` to produce the same timeline item/detail shape the store uses, then projects that store-shaped value.
`CodexThreadHistorySnapshot` uses that projector instead of maintaining its own raw-item switch, and the example app's main and side-chat command/file/tool start and completion paths also call the shared transcript session.
`CodexChatTranscriptState` now owns live transcript identity, deltas, upserts, and stream finalization for both the main transcript and the example side chat.
`CodexChatTranscriptNotificationRouter` now owns the live app-server notification matrix for transcript-affecting events: assistant deltas, command output, file-change output and patches, plan deltas, turn plans, turn diffs, MCP tool progress, and notices.
The example app delegates both main-chat and side-chat transcript updates to shared UI sessions, then keeps only orchestration state such as token usage, app-specific global actions, and subagent coordination.
`CodexAgentStateMapper` now keeps a `CodexChatTranscriptState` per subagent thread, so child-thread assistant, command, file-change, plan, tool, notice, and stream-finalization behavior uses the same merge rules as the main transcript.
`CodexAgentItemParser` now owns raw subagent item detection, descriptor extraction, collab-agent payload parsing, metadata display-name parsing, user-message extraction, and small item display labels. `CodexAgentStateMapper` now uses that typed parser boundary and keeps the stateful work: lifecycle events, subagent upserts, transcript syncing, metadata caches, and side-chat visibility.
`CodexAgentNotificationRouter` now owns child-thread raw notification dispatch into `CodexAgentStateMapper`, so the example no longer carries the method switch for subagent command/file/plan/tool/notice events.
`CodexActivityLogSession` now owns activity-log insertion order, detail normalization/clipping, and bounded retention. The example app receives activities from shared sessions and app actions, but it no longer owns the local reducer policy for the activity timeline.
`CodexClient` now reduces standard timeline notifications into `CodexCoreStore` before yielding them to notification streams, so UI consumers can read the latest canonical turn snapshot while handling a notification.
`CodexCoreStore` now keeps a `threadSnapshotsByID` index in addition to `activeThread`. Non-active child-thread events are retained as canonical snapshots without hijacking the active thread, so subagent transcript routing can ask the store for child turn state by thread ID.
`CodexChatTranscriptProjection` also maps `CodexTurnSnapshot` and `CodexTimelineItem` into transcript messages, including turn-level plan and diff messages, giving the UI a store-backed projection path instead of only a raw `ThreadItem` projection path.
`CodexChatTranscriptNotificationRouter` now prefers `CodexTurnSnapshot` context for typed turn plan/diff notifications, so if the notification payload and store disagree the transcript follows the store.
`CodexTurnSnapshot` now preserves typed command/file/tool details in an `itemDetails` sidecar keyed by item ID. This keeps the public `CodexTimelineItem` enum source-compatible while making the store the owner of rich transcript payloads.
`CodexChatTranscriptProjection` uses those typed details when projecting store snapshots, so command cwd/exit code, file-change diffs/output, and MCP tool results come from the store-backed path without re-decoding raw JSON.
`CodexChatTranscriptNotificationRouter` now prefers store-projected started and completed items when a turn snapshot is available, so command/file/plan/tool transcript cards can follow the canonical store snapshot instead of re-parsing the notification payload.
`CodexChatTranscriptSession` now owns the UI-facing main transcript session: transcript messages, current turn plan, current turn diff, snapshot-backed notification routing, streaming finalization, reset behavior, and notification turn-ID extraction.
`Examples/CodexChatExample/ChatModel.swift` now delegates main transcript updates to that session and supplies the current store snapshot; notification payloads trigger the event, but the store snapshot owns the actual plan/diff and command/file/tool payloads whenever it can represent them.
`CodexMainChatSession` now composes the main transcript session with main-turn lifecycle state. It owns residual main-chat notification fallback behavior: token/login activities, typed and raw turn completion, store-backed turn chrome sync, subagent start/completion actions, assistant-completion actions, and refresh/follow-up effects.
`CodexNotificationMetadata` now owns UI routing metadata extraction for thread IDs and turn IDs across typed, known, and raw notification shapes. Transcript routing, subagent routing, and the example model use that single helper instead of each re-declaring app-server JSON nesting rules.
`CodexTurnLifecycleSession` now owns active-turn bookkeeping for main chat and side chat: pending/running state, handle storage, active turn IDs, completion matching, failed-start cleanup, and reset behavior.
`CodexGlobalNotificationRouter` now owns the global/session notification matrix for skills changes, thread-started metadata, thread compaction, goal updates/clears, goal turn starts, and MCP startup status. The example receives typed actions instead of switching over typed/known/unknown app-server methods itself.
`CodexChatNotificationPipeline` now owns the UI-level notification routing hierarchy across global notifications, child-thread subagent notifications, and main-chat notifications. The example supplies the current thread ID and store snapshots, then applies simple side effects such as activities, transcript mirroring, agent-state mirroring, refreshes, and queued follow-ups.
`CodexAgentNotificationRouter` now accepts a `(threadID, turnID)` store snapshot lookup and prefers store-projected messages for child-thread items when the store can represent them. Started, live, and completed subagent assistant/command/file/tool payloads plus turn-level plan updates can therefore use the same typed `CodexTurnSnapshot` path as the main transcript instead of re-parsing raw notification JSON.
Goal turn starts now record the concrete turn ID in `CodexMainChatSession` instead of leaving main chat in an anonymous pending state, so matching turn-completed notifications can close the active turn reliably.
`CodexGoalStateSession` now owns active-goal state, pursuit-mode toggling, active goal turn tracking, goal summaries, clear/update transitions, and notification matching for goal turns. The example still performs the network calls and renders activities, but it no longer carries the goal state machine itself.
`CodexPromptStateSession` now owns approval and interactive prompt arrays, store-poll diffing, user-input replacement, prompt resolution, and prompt activity descriptions.
`CodexPromptModels` now owns approval/user-input/MCP elicitation prompt data contracts and server-request response parsing near the prompt session that consumes them.
`CodexInteractivePromptBridge` moved into `CodexCoreUI`, so continuation-backed MCP/user-input prompt orchestration is reusable framework code instead of a private actor inside the example.
`CodexPromptEventSession` now owns approval-store polling and interactive-prompt event task lifecycle. The example still applies prompt activities to its activity log, but it no longer stores prompt event tasks or duplicates the polling/listener loops.
`CodexPromptStateSession` now also owns prompt response routing: approval resolution, store-backed user-input response, and bridge-backed MCP elicitation response. The example starts UI tasks and displays activities, but it no longer switches on prompt kind or knows which prompt family resolves through which backend.

The example exposes prompt arrays and starts/resolves prompt flows through that session instead of wiring `CodexPromptStateSession`, `CodexPromptEventSession`, and `CodexInteractivePromptBridge` directly.
`CodexComposerStateSession` now owns draft text, side-chat draft text, attached skill inputs, selected file mentions, mention results, follow-up behavior, queued follow-ups, submission input assembly, and failure restoration. The example still creates network turns, but no longer mutates those composer collections across unrelated methods.
`CodexSideChatSession` now owns the local side-chat state, side-chat transcript state, side-chat turn lifecycle, side-chat notification fallback routing, store-backed transcript projection, and stream finalization. The example still forks and sends turns, but it no longer owns the side-chat reducer.
`CodexThreadListSession` now owns recent-chat list state, visible-thread filtering, duplicate merge rules, project summary recomputation, and thread-search loading/error/results state. The example still fetches from the app server and renders activities, but raw thread-list/search responses no longer mutate scattered example properties directly.

`CodexThreadListModels` now owns thread summaries, thread-search results, and project summaries near the list session that consumes them, instead of leaving that raw list/search model cluster inside the giant chat model file.
`CodexThreadHistorySession` now owns thread-history loading/restoration: reading raw parent history, reading child subagent thread history, applying child history to the snapshot, resetting the main transcript, replacing the agent mapper, resetting side chat, and producing the restore activity. The example still decides when to resume/fork and how to display errors, but it no longer stitches raw history into UI state itself.
`CodexThreadSession` now owns current-thread and side-chat-thread handles plus start/resume/fork/archive/focused-fork primitives. The example still attaches UI activities and history hydration, but it no longer stores duplicate thread handles or reimplements the thread lifecycle primitives inline.
`CodexIntegrationCatalogModels` now owns MCP server status and plugin summary raw app-server catalog parsing instead of leaving that integration parsing in the chat model file.
`CodexIntegrationCatalogSession` now owns MCP/plugin loading state, disconnected messages, raw response application, MCP startup status merging, plugin load errors, and activity descriptions. The example still calls the app-server endpoints, but it no longer mutates the catalog arrays/error/loading flags directly.
`CodexIntegrationCatalogSession` now owns MCP/plugin raw endpoint orchestration as well, so the example no longer repeats begin/fetch/apply/fail blocks for those catalogs.
`CodexChatConfigurationModels` now owns connection state, approval/permission profile selections, model/reasoning selections, collaboration mode options, and slash-command catalogs. `CodexChatModels` is back under 1k lines and now only owns chat action handlers plus transcript message/detail models.
`CodexChatConfigurationSession` now owns the mutable configuration state machine: approval option fallback, plan-mode reasoning coupling, model option selection, model/reasoning normalization, slash-command load/reset, turn parameter overrides, fast mode, and reasoning cycling. The example still performs network calls, but it no longer carries that selection logic.
`CodexChatConfigurationSession` now also owns permission-profile, collaboration-mode, model-list, and slash-command raw refresh flows. The example no longer repeats four nearly identical catalog do/catch reducers.
`CodexThreadHistorySnapshot` now lives in its own history restoration file and delegates item-to-message conversion to `CodexChatTranscriptProjection`, leaving the old inline user/command raw parsing helpers deleted.
`CodexAgentPanelModels` now owns activity rows, subagent/side-chat panel state, and prompt suggestions, so `CodexCoreUI/CodexChatModels.swift` no longer imports SwiftUI just to provide panel tint metadata.
`CodexChatStreamSession` now owns main-turn, side-chat-turn, and global-notification stream tasks: task replacement, cancellation, reset, notification delivery, and finish callbacks. The example still decides what to do with each notification, but it no longer stores three direct task slots or duplicates the stream-consumption loops.
`Examples/CodexChatExample/ChatModel.swift` no longer mirrors `CodexAgentStateMapper` and `CodexSideChatSession` into stored `lifecycleEvents`, `sideChat`, and `subagents`. Those values are computed from the owning sessions, removing another UI-level second truth.
`CodexMainChatSession` now also owns main turn, queued follow-up, steered follow-up, and goal-submission transcript/activity choreography. The example still creates network turns, but it no longer hand-mutates pending lifecycle, user/system transcript messages, and failure activities around every send path.
`CodexSideChatSession` now owns side-chat submission choreography: opening the local side chat, marking the side turn pending, appending the local user message, and recording failed-start transcript/activity state. The example now supplies the network call and turn handle only.
`CodexChatNotificationRuntime` now owns the UI runtime boundary between notifications, `CodexCoreStore`, and the main/side-chat sessions. The example no longer keeps a local `storeTurnSnapshot` helper or separate main/side snapshot-routing forks; both paths ask the same runtime for store-backed turn context before projecting transcript updates.
`CodexChatRuntimeState` now owns the main chat, side chat, goal, subagent mapper, and integration catalog sessions as one runtime state graph. Notification routing, side-chat routing, turn finishing, and history restore enter through that boundary instead of the example threading five mutable session values through each call site.

`CodexComposerStateSession` now owns slash-command routing for composer-affecting commands. The example still performs host actions such as opening side chat, forking, compacting, and refreshing MCP state, but it no longer carries the command-ID decision tree or direct draft/skill mutation matrix.
`CodexNotificationPresentation` now owns residual notification display labels for item types, method names, and token-usage summaries. Main chat, side chat, transcript routing, and agent item parsing now share one naming policy instead of keeping small divergent copies.
